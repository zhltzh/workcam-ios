## Storage and security

CaptureStore writes the original AVFoundation JPEG into Application Support/Evidence/.pending-UUID/photo.jpg, rereads it and compares SHA-256 with the input bytes. EvidenceRecord stores the photo UUID, hash, nested backend SignatureManifest, public key SHA-256 identifier and capture status. A separate signature.der preserves DER bytes. Atomic protected file writes precede an atomic directory move to UUID. Pending directories are excluded from normal verification and listed as incomplete on subsequent inspection. Old Application Support/Captures photos remain intact and unsigned.

CryptoKit SecureEnclave.P256.Signing.PrivateKey creates a hardware key, guarded by SecureEnclave.isAvailable. Keychain stores its opaque device-bound wrapped dataRepresentation using WhenUnlockedThisDeviceOnly. No raw private scalar export API is used. Failure to create/load/sign preserves an Unsigned record with an error. No software fallback exists. Public key uses 65-byte x963Representation, signature uses DER encoded in standard padded Base64. Hardware acceptance remains Pending.

Each capture is an independent genesis record, sequence 0 and previous hash null. This prototype does not implement inter-record chain linkage. Location is null. Non-null location is deliberately rejected pending tested Python float-format parity. Device ID is the public-key hash. Timestamps are ISO8601 UTC device-reported strings, not trusted clock assertions. A production capture-time pipeline remains future work.

Evidence Debug reloads committed records and recalculates photo hashes and ECDSA verification when opened, including after relaunch. Persisted status is advisory and never used as proof. Reverify refreshes results. Tamper Detection tests copies in memory, preserving originals. record.json is the recovery marker, incomplete pending folders remain isolated for inspection. Disk exhaustion can leave a pending folder. No cleanup UI exists. Fully replacing the photo, manifest and public key or stripping signature metadata is outside this unanchored local trust model. Local status does not establish server verification, photo truth, hardware attestation or legal effect.

## WC-M003-R1

Failure assertions now accept EvidenceError.invalid exclusively, failing on unrelated exceptions. Malformed cryptographic public-key/DER parsing is normalized to invalid at the verification boundary. Tests cover missing manifest, missing/empty/corrupt signature metadata, deleted detached DER, mismatched independent key, genuine unsigned records and forged persisted statuses. Test-only software keys create fixtures for these checks and never enter capture code.

Evidence Debug now loads the existing Keychain Secure Enclave reference without creating a replacement key, then compares its public key and corresponding signed device_id. This establishes consistency with this installation's key, not registered device identity or server attestation. Missing Keychain, locked device or invalid reference causes inspection failure. The standalone mathematical verification helper labels unchecked key provenance explicitly. Persisted record status and local-status.txt are never inputs to verification. Stripping all signing metadata can at most produce Unsigned, never local verification passed. Distinguishing a fully rewritten unsigned record from a genuinely unsigned record requires an external trusted ledger.
