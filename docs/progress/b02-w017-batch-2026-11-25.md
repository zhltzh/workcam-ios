## 关键设计决策

1. **成功记台账、失败不记**：同 batch_id 重试失败子集时，已成功项回放存储结果（不重做），失败项重新执行——「可恢复失败」的直接实现。与 W008「确定性失败记台账」不同，原因：批量管理的失败常是暂态（原图未上传等），钉死台账会丧失重试能力。
2. **per-photo request hash**（非整批 hash）：重试只带失败子集时，其余照片的 hash 依然匹配存储值，duplicate 路径成立。
3. **move 整批前置校验**（任务硬性要求）：任何一张照片或目标项目不合规 → 整批 400 + 逐张明细 + **零执行**。被 issue 关联的照片不可移动（避免造成 W013 禁止的跨项目 before/after 关联）；归档项目内照片冻结不可移。
4. **稳定分页**：keyset on `(sort_value, photo_id)`，行值比较原子；无 offset → 插入行零漂移（测试用三个插入位置钉死）。
5. **导出＝快照语义**（同 W012 报告）：已成功照片的 manifest 条目从台账复用；重试生成新 export 包（旧包不可变）。
6. **水印批量**：渲染在台账事务外（CPU 密集），靠 W011 幂等探测兜底中断重放。
