## 4. Key real results (PoC, c2pa-rs 0.92.0 / c2pa-python 0.39.0)

- Offline (no TSA) JPEG signing works; overhead is ~constant
  **+35–36 KB** (5,355 B → 40,684 B; 322,116 B 12MP-class → 358,447 B,
  i.e. +11.3%; sign 56.2 ms / 242.8 ms; read 3.6 ms / 7.5 ms).
- Trust model is explicit and measurable: read back with no anchors →
  `Valid`; with the PoC test CA installed as anchor → `Trusted`;
  one flipped byte → `Invalid`.
- HEIC round-trip works (19593 B → 23483 B, 42.2 ms sign, state `Trusted`).
- Derivative with `parentOf` ingredient works (chain depth 1, `Trusted`).
- SDK enforces the spec 2.5 §13.5.1 certificate profile at signing time
  (rejected self-signed leaf; rejected CA+leaf missing SKI/AKI).
- Online TSA attempt failed in sandbox (SDK native HTTP does not use the
  Windows proxy; recorded honestly — mechanism conclusions cite the spec).
- PyPI beware: the bare `c2pa` package (1.4.1, GPLv3) is NOT the official
  SDK; the official one is `c2pa-python` (MIT OR Apache-2.0).

## 5. Findings that touch other workstreams

- **W023 F1 confirmed in source** (`Evidence.swift`): Mac payload hardcodes
  `location=none` and v1.1-only. Any C2PA location assertion must wait for
  that fix; flagged as gap G3 / precondition for B02-W022.
- **C2PA has no cross-record hash chain**: WorkCam's anti-reorder evidence
  has no C2PA equivalent; it must stay a WorkCam-native guarantee (G2).
- **Offline re-timestamping has a standard mechanism** (spec 2.5 §16.7.2
  time-stamp assertion) structurally analogous to our time-anchor receipts,
  but requires a trust-listed TSA and must happen before the signing
  certificate expires (G5).
