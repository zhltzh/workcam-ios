## T15 工程缺陷辅助识别（POC_READY，算法骨架层）

1. **解决了什么**：没有评测底座。先建了三件事——像素级 ground truth
   的合成裂缝生成器、经典基线检测器、精确指标套件。
2. **真实运行了什么**：纯标准库 128×128 合成图 + 暗阈值 + BFS 连通域
   + **细长度**判据（bbox 对角线²/像素数）。
3. **数据与结果**（合成图，SYNTHETIC）：
   - 裂缝图：object 检出 1/1，recall 0.76
   - 污渍图：0 检出（细长度 ~2 vs 裂缝 ~98，分界干净）
   - 无预测时 precision=None（不是 0.0 装成有分数）
4. **调试中发现并修复的真缺陷**（合成基准的价值证明）：
   - bbox 伸长率判据对**斜裂缝**失效（近方形 bbox）→ 换方向无关的细长度
   - 抖动加在步进增量上使裂缝断裂成 <min_pixels 碎片 → 改慢变正交摆动
   - bbox 当像素预测把空白计入 FP 压垮 precision → 组件像素级评估
5. **已知限制**：无模型、无真实照片、无公开数据集授权评估；基线是
   未来 Core ML 模型必须击败的参照物，不是产品能力。
6. **能否进产品**：评测协议可以；检测能力不能（需要 Mac 侧模型选型
   与真实数据实验）。

## T16 语音记录与自动报告（POC_READY，协议层）

1. **解决了什么**：转写文本被直接改写、来源不可追溯、报告字段可凭空
   编造。
2. **真实运行了什么**：链条协议——音频哈希（write-once）→ 机器转写段
   （带识别器版本、段级时间戳、超音频时长即拒绝）→ 人工修正层（append
   -only、记录编辑相似度）→ 报告字段**强制引用来源段**。
3. **测试**：7 项——修正层叠加、幽灵段拒绝、双重编辑拒绝（append-only）、
   伪造时间轴拒绝、**无引用字段拒绝（防编造核心）**、human_corrected
   无编辑记录即拒绝、审计轨迹完整。
4. **已知限制**：iOS 端语音识别（Speech framework on-device）无法在
   Windows 评估——工地噪声/口音/术语实验全部 DEVICE_PENDING（Mac）。
5. **能否进产品**：协议可冻结；识别质量未知，报告草稿功能以"每字段
   可溯源"为先决条件——已满足。

## T17 照片对比与变化检测（POC_READY，算法骨架层）

1. **解决了什么**：无配准的差异检测会把曝光变化当"变化"。
2. **真实运行了什么**：平移配准（**内部窗口去均值 MAE**）→ 对齐 →
   窗口去均值差异 → 4 连通变化热区。纯标准库 64×64 合成对。
3. **数据与结果**（SYNTHETIC）：
   - 平移 (5,-3) 精确找回（配准方向 = 施加运动的**逆**，首版方向搞反
     已修正留注释）
   - 真变化矩形检出 1/1；**曝光 +30 零误报**（归一化/去均值生效）
   - 未配准的错位在配准后正确归零（演示配准必要性）
4. **调试中修复的真缺陷**：
   - 全图归一化的均值/std 被**复制边框像素**污染（小图 ~30%）→ 归一化
     域错位、配准落在貌似合理的错误位移 → 改窗口去均值
   - 周期纹理 `(x*7+y*3)%40` 存在平移混叠（不同位移同相位）→ 改每像素
     哈希纹理
   - δ 峰残差面下 2px 粗扫必然错过 → 全程 1px 精扫（注释注明大图需金字塔）
5. **已知限制**（写进 ChangeReport.limitations，随每份报告输出）：
   仅平移配准——视角/尺度变化会产生虚假区域；合成灰度测试台，真实照片
   未测。真实配准需 Accelerate/vImage（Mac）。
6. **能否进产品**：不能（算法层）；作为 iOS 端 vImage 实现的行为合同
   可以。
